# Configuration

Provider configurations are stored in `/etc/icingaweb2/modules/sso/providers.ini`
and are managed through the Icinga Web frontend.

## Adding a Provider

1. Navigate to `Configuration → Modules → sso → Providers → New`.
2. Fill in the required fields (see below).
3. Click `Save`. Icinga Web SSO will contact the provider's discovery endpoint to validate connectivity first.

## Provider Settings

### Basic Settings

| Field           | Description                                            | Example                                                 |
|-----------------|--------------------------------------------------------|---------------------------------------------------------|
| name            | Display name shown on the login button                 | GitLab                                                  |
| base\_url       | URL of the OpenID Connect provider                     | https://git.icinga.com/.well-known/openid-configuration |
| client\_id      | Generated by the OIDC provider                         | deadbeefc0decafecafec0debeefdead                        |
| client\_secret  | Generated by the OIDC provider                         | gloas-cafec0debeefdeaddeadbeefc0decafe                  |
| scopes          | Space-separated; configure these in the OIDC provider! | openid profile offline\_access groups                   |
| redirect\_url   | Auto-filled; configure the same in the OIDC provider!  | https://example.com/sso/oidc/redirection-endpoint       |
| username\_claim | Claim that holds the username                          | preferred\_username                                     |
| map\_groups     | Import group memberships from the provider             | yes/no                                                  |
| groups\_claim   | Claim that holds the list of groups                    | groups                                                  |

Claims are first read from the ID token. If a required claim is absent there, Icinga Web SSO
automatically falls back to the provider's userinfo endpoint.

A providers group\_claim can be an array or a comma seperated list. 

### Advanced Settings

| Field              | Description                                                   | Example             |
|--------------------|---------------------------------------------------------------|---------------------|
| username\_search   | PCRE regex to match against the upstream username             | `/^(.*)$/i`         |
| username\_replace  | Replacement string; back-references like `${1}` are supported | `gitlab-user-${1}`  |
| groupname\_search  | PCRE regex to match against upstream group names              | `/^(.*)$/i`         |
| groupname\_replace | Replacement string; back-references like `${1}` are supported | `gitlab-group-${1}` |

To strip the domain from usernames such as `jdoe@example.com`, use one of these
settings. In both cases, the user logs in as `jdoe`.

* Set username\_search to `/@.*$/` and leave username\_replace empty. This
  deletes the matched domain.
* Set username\_search to `/^([^@]+)@.*$/` and username\_replace to `${1}`.
  This keeps only the captured part before the `@`. Set username\_replace to
  `entra-${1}`, for example, to also add a prefix.

## HTTP Proxy

Server-side requests to the OpenID Connect provider use Guzzle's proxy environment
settings. Set `HTTPS_PROXY` to the proxy URL for HTTPS requests and `NO_PROXY` to a
comma-separated list of hosts or domains that should bypass the proxy. Make these
variables available to the PHP instance running Icinga Web. The module has no
separate proxy setting.

See [Guzzle's environment variable documentation][guzzle-proxy] for details.
With Apache and `mod_php`, use [Apache's `SetEnv` directive][apache-env].
For passing variables to PHP-FPM, see the [nginx][nginx-fastcgi] or
[Apache][apache-fastcgi] documentation. These settings affect server-side provider
requests and do not configure the user's browser.

[guzzle-proxy]: https://docs.guzzlephp.org/en/stable/quickstart.html#environment-variables
[apache-env]: https://httpd.apache.org/docs/2.4/mod/mod_env.html#setenv
[nginx-fastcgi]: https://nginx.org/en/docs/http/ngx_http_fastcgi_module.html#fastcgi_param
[apache-fastcgi]: https://httpd.apache.org/docs/2.4/mod/mod_proxy_fcgi.html#proxyfcgisetenvif

## Security Notes

* Managing providers requires the `config/modules` permission.
* Client secrets are stored in plain text in `/etc/icingaweb2/modules/sso/providers.ini`.
* Installing the `openssl` extension is strongly recommended for better random values.
* The module relies on HTTPS for transport security. Do not use HTTP providers in production!
